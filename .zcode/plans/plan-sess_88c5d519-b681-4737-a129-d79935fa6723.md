# GitHub Actions 自动打包机制

## 目标
推送代码后自动完成"编译 → 密钥门禁 → DMG 打包 → 发布"，取代当前「本地 dist.sh + 手动传 Release 附件」的流程。

## 新增文件：`.github/workflows/release.yml`

**触发条件（三种）**：
- `push` 到 `main` → 构建并将产物更新到滚动预发布 **latest**（始终指向最新代码）
- 推送 `v*` 标签（如 `v0.1.1`）→ 创建**正式版本 Release**（版本化发布，发版时先改 Info.plist 版本号再打 tag）
- `workflow_dispatch` → 支持在 GitHub 页面手动触发

**构建 Job**（`runs-on: macos-latest`，公开仓库免费）：
1. checkout
2. 执行 `./dist.sh`（Universal 编译 + 签名 + `check_no_secrets.py` 门禁，逻辑与本地完全一致；CI 钥匙串为空，`sign.sh` 自动回退 ad-hoc 签名，与现网行为相同）
3. 上传 workflow artifact（每次构建留档，供下载调试）
4. 发布步骤（用 runner 自带的 `gh` CLI + `GITHUB_TOKEN`，`permissions: contents: write`）：
   - main 推送：删除并重建 `latest` 预发布（`--target` 指向本次 commit SHA，附件 --clobber 覆盖，notes 里自动写入 SHA256 + 构建来源 commit）
   - tag 推送：`gh release create` 版本化发布，附 DMG + SHA256
   - 全程走 GitHub API，不向 main 推送任何东西，**与已开启的分支保护不冲突**

## 配套调整
- README「构建」小节补一句：推送 main 自动构建 latest 预发布，发正式版打 `v*` tag
- 本地 `dist.sh` 保留（手动出包能力不变）
- 分支保护设置不变；后续如需"PR 必须构建通过才能合并"，只需在此 workflow 加一个 `pull_request` 触发并在分支保护里启用 required status checks（本期不配）

## 注意事项
- CI 产物是 ad-hoc 签名（本地稳定证书在你的钥匙串里，CI 无法访问）；对下载用户行为一致（右键打开）。若以后想要 CI 稳定签名，可把自签证书经 GitHub Secrets 注入，属可选增强，本期不做
- 首次生效：workflow 文件合入 main 后的第一次 push 就会自动触发构建，跑通即验证完成

## 验证与交付
1. 本地 `actionlint` 式自查（yaml 语法/结构）后提交推送
2. 观察 GitHub Actions 首次运行：构建成功、latest 预发布出现且 DMG/SHA256 正确
3. 沿用密钥门禁（workflow 内置步骤）
